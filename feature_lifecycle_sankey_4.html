Feature Lifecycle Across Models
The same 4 models as before — ADR, Conversion, Pickup, F&B — but now laid out as 4 sequential levels, one feature per node, so you can trace each feature's journey model by model instead of collapsing the reuse pattern into a summary bucket. A ribbon means the feature is used in both models it connects; a node with no incoming ribbon is a fresh entry at that level, and a node with no outgoing ribbon drops out after that level. Built from the same real per-model feature lists and split counts as feature_distributions.html. Both nodes and ribbons now carry real importance twice over — opacity and thickness, both scaled to the feature's real share of that model's total splits (importance / total_splits × 100, the same "% of splits" figure the original dashboard reports). Solid and full-height means a large percentage, faint and thin means it barely gets split on (or is unused). The % scale is shared across all four levels, so a bar's size means the same thing everywhere — 7% at ADR draws exactly as thick as 7% at F&B. Ribbons taper between the two models they connect, so a feature that matters a lot in one model and barely at all in the next visibly narrows and dims as it crosses. Row position stays fixed either way — only the drawn band grows or shrinks around it.

What this shows

36 features run straight through all four models unchanged — same feature, same relative position, at every level. That's the indigo band spanning the full width.

6 features join at Pickup and carry on to F&B (purple) — num_fnb_types, Urgency_Index, Account_Prior_Booked, budget_amount, has_fnb_requirements, is_meeting_only — never used by ADR or Conversion at all.

22 features join at Pickup and go no further (amber) — mostly the 13 market_seg_* one-hot columns plus event_type_enc, room_block, event_format_enc and a handful of others. They're Pickup-exclusive dead ends.

5 features appear only at the very last level (pink) — num_sessions, rate_spread, avg_room_utilization, smerf_demand_30d, has_dinner — F&B-specific signals with no upstream presence.

Source: real per-model feature lists and split counts from feature_distributions.html (itself read from the exported xgboost_trees_data_v7.js) — nothing here is estimated. Node height is uniform per feature (one row = one feature), not weighted by split count, since this view is about membership across models, not magnitude — split counts are still real and shown on hover. Within each of the 4 color groups, features are ordered by combined real split count across the models that use them, so the busiest shared features sit at the top of their band.
