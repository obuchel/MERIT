Source: real exported model (xgboost_trees_data_v7.js) for the full feature list and split-count ranking; real training data (rfp_training_data_complete_v3.csv) for distributions. tr_transient_occ_of_available, tr_transient_rooms_turned_away, and tr_displacement_pressure aren't stored in v3 — they're recomputed here with a real stay-window join against Nexus_Transient_Demand_v2.csv, matching the report's Section 3.4 join description. market_seg_*, is_meeting_only, and group_size_tier_clean_enc are derived from their raw source columns using the documented encoding. Extreme values are clipped at the 1st/99th percentile per numeric feature so outliers don't compress the rest of the histogram (skew/shape below is computed on the full, unclipped values, not the clipped chart). Shape chip: a column with only two distinct values (the many 0/1 flags among these features, plus the one-hot market_seg_* columns) is labeled "Binary flag" with the share that's 1, since skew/kurtosis describe continuous shapes and a two-point split isn't one. For everything else: |skew| < 0.5 with low excess kurtosis is "Approx. normal" / "Roughly symmetric"; |skew| ≥ 0.5 is skewed (≥1.5 "strongly"); very negative excess kurtosis with low skew reads as "Flat / uniform-like". It's a heuristic, not a normality test — always check the curve itself too, since skew/kurtosis alone can't flag bimodality. Categorical features (event type, lead source, event format) show group share instead of a histogram.
  1. note"Split count in real trees" means every tree inside that trained XGBoost model was walked node by node, counting every internal node that splits on this specific feature — a literal count read out of the exported model file, not an estimate or a formula-based importance score. A bigger number means the model branches on that feature more often when routing an RFP through its trees. The percentage next to it is that same count divided by the model's total split count (the sum of every feature's splits in that model — 10,030 for ADR, 2,113 for Conversion, 1,513 for Pickup, 9,035 for F&B), so e.g. "7.3%" means just over 1 in 14 of every split decision that model's trees ever make lands on this feature. The percentage is comparable within a model (7.3% vs. 3.6% is genuinely "about twice as central"), but the four models have very different totals, so the same percentage in two different models doesn't mean the same number of actual splits — check the raw split count too if that distinction matters.
